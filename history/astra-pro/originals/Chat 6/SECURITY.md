# Product trust, privacy and abuse contract

The Writer app is not an independent hardware witness. A sandbox, code signature, Keychain key, native key event or Swift implementation does not alone establish human composition. The frozen protocol owns the conditional claim and exact algorithm; product UI cannot strengthen it. The prepared Foundation projection helper is not a verifier. All positive authority decisions come from the complete independently selected protocol policy and evidence.

## Boundaries

- **Source:** exact UTF8 bytes and immutable revision identity; Swift canonically equivalent Strings are not interchangeable. HWP applies to source/scope, not automatically title fields, publishedmetadata, renderedPDF orDOCX.
- **Observation:** consented in-document events only. No global typing, cameras, screen recordings or research-history surveillance. Opaque native/system/assisted updates are unknown or assisted, never invented device events. Local app journal is not an evaluated capture profile.
- **Execution:** frozen native P/V/R semantics, strict parser/resources, no untrusted code loading or receipt-mode fallback. Old release meanings remain pinned. No empirical model/report/authority is fabricated.
- **Keys:** distinct Nostr BIP340, HWP author/capture/evaluator and local encryption purposes. Keychain errors are errors; never replace an inaccessible encryption key. No real secret in logs, defaults, crash telemetry, screenshots or repository. Signing only after explicit publish/participation intent.
- **Network:** offline until opt-in; ordinary files use native provider grants. Relay messages and imported release/proof URLs are untrusted. No cleartext fallback for draft encryption, no automatic upload of private history, no network-dependent typing or sound.
- **Filesystem:** safe bounded archive paths, no symlinks/traversal/duplicate aliases, no plaintext private WAL, atomic coordinated saves, conflict-preserve-both. Clipboard not read globally or cleared as punishment.
- **Focus:** voluntary public-API friction, clear restrictions, always available emergencyexit and complete teardown. No force-quit prevention, privileged helper, process killing or data destruction.

## Mandatory adversarial tests

Exercise log/response/error scanning for raw keystrokes and nsec, plaintext private drafts on relaywire, forgedevent/signature/role, NIP44 length/MAC/padding, stale ACK generations, outbox duplicate sends, identityswitch, huge/recursiveCBOR, archivebomb/pathtraversal, malformedXML/Markdown/links, corrupted encrypted recovery, inheritedprovenancetextsubstitution, scope/target/profile/model/downgrade, metadata-only proofmismatch and fabricatednativecausefields. Test all these without real user keys or participant evidence.

Disable rawHTML/executable content and remote asset fetch in preview. Opening a remote URI is an explicit action, never something a malicious Markdown image starts while typing. Restrict accepted link schemes and show unsafe links literally. Unrecognized imported proof modes/policies are NOT PROVABLE; no author-provided approved Boolean grants authority.

## Permissions and distribution

AppSandbox and HardenedRuntime are on from Stage01. Request user-selected files/outgoingnetwork and optional mic only for corresponding features. Speech privacy description/authorization is requested just in time. No Accessibility/InputMonitoring/ScreenRecording/FullDiskAccess entitlement, global eventtap, MDM or insecure update framework. DeveloperID credentials/signingpasswords stay in owner-controlledKeychain/CI configuration; PR CI never gains signingsecret access. Do not share fontfiles.

## Data retention and disclosure

Current source can be local/provider stored at user choice. Detailedhistory stays encrypted locally by default; recording requires explicit informed consent, including deleted text/timing sensitivity. A synced Markdown file, relaydraft or documentZIP does not silently include history. Encrypted private exports require a separate explicit key/consent and explain loss/metadata risks. Removeprivatehistory is separate from deleting published material; erasure cannot be guaranteed on remote relays/backups. No telemetry service is required in MVP.

## Nonclaims that must survive marketing and code

NOT PROVABLE is not AI-generated, dishonest or nonhuman. Known provenance is not sufficient composition evidence. Nostr signature is not HWP. No empiricalcapture profile is shipped approved. No guaranteed prevention of mentaltranscription, owner-controlledOS fabrication, unlimitedadaptiveattempts, relay deletion, networkretention or perpetualcryptographicsecurity. Any exported proof clearly states exact scope, release, mode and trustedpolicy. HWPscience can improve later without changing old assertions.
