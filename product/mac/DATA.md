# Document, recovery and provenance data contract

> Recovered historical preparation; read the [current recovery notice](RECOVERY-NOTES.md) before relying on source availability or test claims.

## Files and ownership

The user's source document is an ordinary exact UTF-8 `.md` or `.txt` file. It is not an opaque app database record. Nostr Writer opens/saves through NSDocument and user-granted URLs; Finder, iCloud Drive and Google Drive for desktop remain the file owners/providers. Never write hidden HWP logs into a provider-synced directory by default. Never depend on a hardcoded `~/Library/CloudStorage` or iCloud path. Google Docs/Drive API integration is not part of the product. [A04,G01]

App-private metadata/recovery/history/outbox reside in the sandbox Application Support directory, owned by the app. A local SQLite database indexes DocumentID (UUID), selected URL bookmark, source identity/fingerprint, revision, title/publish metadata, owned asset references, capture handles and signed snapshot references. The user's filename/title is presentation metadata, not a cryptographically certified part of source content unless actually present in that source.

Private history and recovery bodies are encrypted before disk using CryptoKit AES-GCM and a distinct installation key stored WhenUnlockedThisDeviceOnly in the app's Keychain service. Use a fresh random nonce for every chunk; authenticate format version, document UUID, recording UUID, monotonic chunk index and previous committed chunk reference as AAD. Do not derive nonces from text, timestamps or restarted counters. Key loss/denial is an explicit unavailable state; never silently replace the key. Index metadata can reveal file names and activity; document this instead of claiming full anonymity. No raw drafts, event bodies, nsec, tokens or clipboard contents in logs, crash reports, UserDefaults or Spotlight records.

Use one actor-owned SQLite connection with WAL, prepared statements and explicit transactions. Store immutable publication bytes and their outbox state transactionally. Recovery/history chunks use an append-before-ack discipline with fsync at a maximum one-second checkpoint interval while active, on Save, on resign/close and before enqueue/finalize. Normal app termination flushes synchronously within a bounded graceful-shutdown path. The last uncheckpointed ≤1-second segment may be lost on abrupt power failure; the UI never labels it durable. An incomplete chunk is a recording gap, not a reconstructable perfect history. Keep independently readable source saves so damaged private state does not strand the document.

## Revisions and edits

Each DocumentSession has one incrementing UInt64 revision and a SourceSnapshot: UUID, revision, exact UTF-8 bytes, byte count and SHA-256. Equality for integrity is byte equality/digest, never Swift `String ==`, which can compare canonically equivalent Unicode. HWP scope is UTF-8 bytes; AppKit selections are UTF-16; the prepared coordinate conversion rejects split scalars and invalid ranges. Display graphemes and native word counts do not replace protocol coordinates.

An EditCommand has an ID, expected pre-revision, scalar-aligned affected range, replacement bytes, observed/declared source category, command origin and undo group. Sources include direct candidate, paste, internal copy/move, restored/imported source, spelling/grammar correction, completion, dictation, translation/generated replacement, metadata-only and unknown. Do not guess provenance from insertion length. A known source is not necessarily admissible capture. All changes enter the gateway, including menu actions, drag/drop, Services, replace-all, restored drafts, attachment insertion and programmatic updates.

Application-generated Markdown delimiters are transformations too. Bold/list/quote shortcuts may be used, but their inserted syntax must not inherit a direct-composition root without the frozen protocol permitting it. Literal delimiters typed by the person are recorded as actual candidate input. Style changes/preview syntax highlighting never mutate text. Keep the app's descriptive source annotations separate from the frozen algorithm's authoritative atom ancestry.

Undo/redo restores original bytes and recorded ancestry, not newly created typing. Cut/move and internal copy reference actual original identities where the record can do so; repeated occurrences cannot manufacture composition evidence. Save As/Duplicate creates a new file and DocumentID with an explicit derivation/import link; it is not a fresh human typing record. Rename/move of the same file retains document identity and recorded histories after coordinated file identity reconciliation.

## Observation lifecycle

A recording epoch begins only after consent and starts from empty state or an explicit unproven import. It records actual native event/delivery/mutation observations. File load, external provider revisions and NIP-37 restores are imports, never simulated key events. The product can collect descriptive native observations without claiming that the path is independently evaluated; HWP admission remains unavailable until justified.

For a future admitted HWP capture, the exact release, profile, claim, author participation and source parents are selected before acquisition. A newly selected parent source cannot be inserted into an earlier signed start. End the prior capture, begin a new capture with the dependency, and preserve exact boundaries. Reboot, unresolvable clock continuity, app crash, unobserved mutation, capture overflow or missing terminal data cannot be repaired by invented input. A new recording starts; the old one remains incomplete/unproven. Ordinary source text remains writable.

Closing/reopening a document cannot make all its existing wording freshly composed in the new record. The app retains prior records and can preserve wording-origin only under actual compatible proof/history dependencies. Incomplete/unapproved prior material stays unproven. Proofs of earlier valid snapshots remain attached to those snapshots, not automatically current. No later empirical release may retroactively transform a conformance recording into prospective production capture.

## File lifecycle and conflict rules

NSDocument manages its own coordinated read/write lifecycle. Do not put a second recursive coordination layer around its callbacks. Use appropriate coordination for separate asset/archive operations, with short critical sections; never hold a coordinator while awaiting a relay or rendering a whole book. Balance security-scoped access lifetimes and renew stale bookmarks through a user action.

Before async save, snapshot the revision. A completed save of revision n does not mark n+1 saved. Coalesce to the latest pending revision, but never drop an unpersisted signed publish intent. Save writes to a same-volume temporary file and replaces atomically through the coordinated native path. Disk full, permission loss, provider offline, eviction/download cancellation and deleted/moved file are separate recoverable states. “Saved to folder” is local provider acceptance, not remote synchronization confirmation.

When an external version differs while local changes or capture are active, preserve current recovery first, then present conflict resolution. Keep Both creates a dated conflict copy plus a local record link, preserving both exact sources. Keep Local still retains the external version in a recovery copy before replacement. Open External Copy keeps current dirty text safe and opens external bytes as imported content. No automatic time-based last-writer-wins. Do not merge two histories just because a text merge succeeds.

Open same URL twice → focus the existing session. Different byte-identical files are not automatically the same document or parent source. File rename/move notifications may update location; file identity plus explicit user action determines ownership, not basename alone. Removing a recent reference never deletes source; deleting source never silently purges private histories or accepted public events.

## Attachments

Support explicitly selected PNG/JPEG files and Markdown relative image references. An insertion copies approved bytes into a user-authorized sibling `<document-name>.assets/` folder using collision-safe names, then inserts an attributed Markdown image operation. Ask for parent-folder access when the selected-file grant does not cover the asset folder. No automatic network image loading. For existing relative links, request explicit access to the relevant directory and resolve canonically; reject path traversal/symlinks escaping granted scope. HTTPS images require a separate explicit fetch/import action with MIME/size limits, not automatic fetch on open.

Save As/Move offers to copy/move only the app-owned referenced assets and updates links in an explicit source revision; no silent rewriting under an old proof. Unowned external assets are not deleted. Missing or blocked images show alt text plus a warning in preview/export. Caps: 20 MiB per image, 100 MiB total imported assets, 50 megapixels decoded per image; use thumbnail decoding for preview.

## Portable data and deletion

Export Source writes exact bytes. Export Document Bundle makes a ZIP with source.md, sanitized metadata, owned assets, and (only when matching/valid) source.hwp plus a manifest identifying each exact byte object. It includes no Nostr secret, history encryption key, unrelated outbox entries, security bookmarks or absolute local paths. Descriptive provenance in metadata is not an HWP proof. Imports validate paths, symlinks, duplicate names, counts and decompressed limits before writing.

Detailed evidence export is a separate deliberate action naming the sensitivity of deleted text/timing. It can produce the frozen private-disclosure format and required exact source/proof artifacts; never improvise a smaller “proof” by discarding evidence. Default transport is a locally encrypted `.nwprivate` file: ASCII `NWPRIVATE1\n`, a 12-byte random nonce, AES-GCM ciphertext+16-byte tag of the bounded ZIP; that fixed ASCII header is AAD. Generate a new 32-byte random export key per file and display/export it separately as unpadded base64url; never store it inside the archive or sync it automatically. File and key together disclose the evidence. The user can explicitly choose unencrypted disclosure for a trusted verifier with a second warning. Encryption is an app transport, not a new HWP verification mode.

Private import must verify AEAD before parsing ZIP, enforce 128 MiB encrypted input / 100 MiB extracted payload / 4096 entries / 20× decompression ratio, reject absolute/parent/symlink/duplicate paths and then apply stricter HWP limits. Unsupported evidence is retained or rejected as such; it does not gain trust from the archive password/key. No promise of cryptographic erasure across backups: delete local indexed history and keys according to explicit choices and disclose that prior exports/backups may remain.

History retention defaults to until explicitly deleted, with a storage-size display and a warning at 1 GiB. At 2 GiB private-store budget, pause new detailed recording and request cleanup/location action; do not silently discard old records or stop ordinary writing. Current source/recovery/outbox safety has a reserved budget and explicit failures. Every deletion dialog distinguishes local source, private history, local proof copies, local outbox and remote Nostr deletion requests.
