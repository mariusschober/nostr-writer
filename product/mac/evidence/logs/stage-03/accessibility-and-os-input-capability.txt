2. VOICEOVER - NOT MEASURED, and why

  pgrep -fl VoiceOver        -> only "VoiceOver Quickstart" (PID 33156, started
                                Thu Sep 17 22:33:41 2026), which is the onboarding
                                window, not the screen reader
  defaults read com.apple.universalaccess
                             -> voiceOverOnOffKey = 0

So VoiceOver is not enabled on this host. Enabling it is a system-wide
accessibility change that immediately starts speaking and remaps keyboard
behaviour on the machine the owner is currently working on, so it was not
switched on unilaterally. The accessibility inventory in section 1 is the
VoiceOver-relevant contract evidence that can be gathered without that change.
Exact owner action: turn VoiceOver on (Cmd+F5 or System Settings > Accessibility >
VoiceOver) and write, navigate the outline, open the inspector and mark a passage.
The Stage 08 criterion M53 ("All U01-U15 screens pass real Mac visual, keyboard,
VoiceOver, dark/light/contrast/motion/input QA") is the row that owns VoiceOver,
and it is a later stage.

3. SYSTEM DICTATION - available on this host, not exercised (audio capture)

  defaults read com.apple.HIToolbox AppleDictationAutoEnable   -> 1
  defaults read com.apple.assistant.support "Dictation Enabled" -> 1
  pgrep -fl DictationIM
    -> /System/Library/Input Methods/DictationIM.app/Contents/MacOS/DictationIM
       (PID 1668, started Fri Sep 18 14:21:48 2026)

The OS-level dictation input path is therefore enabled and loaded on this host.
The Stage 03 plan requires keeping it distinct from the app's own on-device
feature: "An OS-provided insertion does not prove how the OS processed audio."
Invoking it would capture live microphone audio, so it was not triggered. The
app-side half of that distinction is covered deterministically: an unexplained
insertion is classified `unknown` and an unexplained programmatic change is a
capture gap rather than physical typing
(Stage03EditorTests.testGatewayClassifiesObservedDeliveryWithoutGuessingFromText),
and the app's own dictation never asks for server-side recognition
(`request.requiresOnDeviceRecognition = true`).
Exact owner action: invoke system dictation in the editor and confirm the inserted
text is recorded as an unexplained/assisted insertion rather than physical typing.
