(5) Native spelling correction, performed through the app's own menu:

  Step A (default, correction off): select all, type "teh " -> document is
      exactly "teh "  (no correction).
  Step B: Edit > Spelling and Grammar > Correct Spelling Automatically, then
      select all and type "teh " -> document is exactly "The " (capitalised
      sentence start). The system spelling-correction machinery ran inside the
      app's text view and replaced the misspelled token.

  This is a real native correction observed in the running candidate. It is the
  *automatic* correction path, not a user-accepted correction from the spelling
  panel or a suggestion menu. The accepted path (NSTextView.changeSpelling(_:))
  is classified as knownAssistance(.spelling) and is covered by
  NostrWriterTests/Stage03EditorTests
  testGatewayClassifiesObservedDeliveryWithoutGuessingFromText; it was not
  exercised natively here because the shared NSSpellChecker panel is a floating
  NSPanel that the accessibility layer does not report as a window on this host
  (System Events lists only the document window for process "NostrWriter" while
  the panel is up), and the spelling-suggestion menu did not appear for a caret
  or find-bar selection in this harness.
