WHY THIS RUN
The stage plan's minimum evidence for M19 is "actual supported recognition plus
denied/unavailable/error behavior and deterministic late-callback/range
cancellation checks". Only the anchor/range rule was covered before this run; the
permission ordering, the denied/unavailable states and the late-callback rejection
were real code with no check. They are now driven deterministically.

WHAT CHANGED IN THE APP (no behaviour change)
  - DictationGeneration: a monotonic, non-reusable session token (begin /
    invalidate / isCurrent), the same shape as the accepted TypewriterScrollPlan.
  - DictationGate: the two capability questions (isSupported for a locale,
    requestSpeech, requestMicrophone) as injectable closures. `.live` is the only
    gate that touches TCC; a test never answers a privacy prompt.
  - DictationController.beginSession(at:) opens the session and anchors to the
    exact caret at invocation, before any prompt can move it.
  - DictationController.deliver(transcript:token:) is the single entry point for
    a recognition hypothesis and drops a token other than the current one before
    the anchor is consulted.
  Nothing about start/stop ordering, the anchor, the replacement rule, the
  on-device-only request or the .denied/.unavailable wording changed.

WHAT EACH NEW CHECK PROVES
  1. Unsupported language: with a gate whose isSupported is false, toggle() ends in
     .unavailable("On-device dictation is not available for this language or
     system."), isListening is false, and the speech and microphone request
     counters are both 0 - the app refuses before it would ever prompt, and the
     source bytes are unchanged.
  2. Denied speech: with isSupported true and speech refused, the state settles on
     .denied("Speech recognition permission was not granted."), the microphone was
     never requested (counter 0), no revision was published
     (document.session?.lastMutation is nil) and the source is unchanged.
  3. Denied microphone: with speech granted and the microphone refused, the state
     settles on .denied("Microphone permission was not granted.") after exactly one
     speech request and one microphone request, with the source unchanged.
  4. Late callback after stop: a session opened at offset 3 inserts "hi" at the
     anchor ("abchidef"); after stop() the same token is delivered again with
     " too late " and neither the source bytes nor the published revision change,
     leaving the state .idle. Two independent guards hold: the token is stale and
     the anchor was dropped.
  5. Superseded session: after a session is closed and a new one opened, the first
     session's token is not reused, its callback is dropped (source stays
     "abcdef"), and the current session still applies - "liveabcdef" with the
     recorded origin knownAssistance(.dictation).
