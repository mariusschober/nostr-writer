## Identity and signing

Single active identity; import nsec/64hex, generate with secure randomness or add read-only npub. Derive the event pubkey from the signing key. All secret scalar/point validation follows libsecp256k1/BIP-340. Keychain states missing, locked/denied, invalid data and successful retrieval are distinct; nil never causes implicit replacement. Use an app-specific service, not NostrShot's existing key item. A migration wizard can explain explicit export/import but must not scrape or overwrite another app's key. Identity switching freezes old outbox/draft ownership; retain items under their original identity until that key is available or the user explicitly creates new publication intents.

Sign the raw32-byte event ID once, not its rehash or hex text. Canonical NIP-01 serialization preserves source bytes/Unicode/newlines; do not apply NostrShot's trim-before-publish to long documents. Reject JSON-forbidden C0 controls not covered by the NIP-01 escaping subset in publishing input with an exact location and non-destructive repair choice; do not invent a serializer variant. Tests include multibyte/decomposed accents, backslash/quotes, tab/CR/LF, U+2028, empty tags, code blocks and metadata. Imported relay events must have matching computed IDs and valid signatures before trust/decryption; reject malformed duplicate object keys, integer/length/range errors and ambiguous required draft tags.

## Relay and durable outbox state machine

Store a PublishIntent with source revision/digest, author, kind, stable address, recipients, exact metadata and consent before signing. Store exact signed event bytes/id transactionally **before sending**. Retry uses the identical bytes/id. A new text/metadata revision is a new explicit intent; cancelling an old local item is not retracting an already delivered event. App crash after send/before ACK can cause resend of the same id, not double creation. UI reports relay acceptance, not readership or global permanence.

One RelaySession actor per normalized user-selected relay. Normalize only scheme/host case and defaultport/root semantics; preserve case-sensitive path/query. Reject userinfo/fragments/control chars and insecure remote ws; loopback ws is permitted only in tests/developer configuration. Do not silently discard query or lowercase paths as the old normalizer does. Respect ordinary TLS validation. Use ephemeral networking without cookies/disk cache. Configure maximum message length2MiB and JSON depth/tag/content/item caps before dispatch.

Register pending publication waiters before socket send. Coalesce same-id concurrent requests or retain multiple observers without replacing an unresolved continuation. All paths—accepted/rejected ACK, send failure, timeout, cancellation, disconnect, shutdown and generation change—resolve once. Connection timeout must cancel/remove waiters, not leave an unresumable task-group child. Capture a generation ID in receive/delegate/ping callbacks; stale callbacks cannot tear down a new socket. Retry with bounded exponential backoff1–60s plus jitter; keepalive60s only for actively used connections; sleep/offline suspends reconnect storm. Default publish ACK deadline8s; first positive ACK reports accepted while remaining results continue to the durable item.

Implement EVENT/REQ/CLOSE, inbound EVENT/OK/EOSE/CLOSED/NOTICE and AUTH. Subscriptions have per-connection IDs≤64 chars, exact filters, cancellation/CLOSE and bounded results. NIP-42 challenges sign kind22242 with relay+challenge tags only after that relay is user-approved; never sign arbitrary requested content or repeatedly loop AUTH. Relay status/NOTICE is untrusted text, sanitized/capped in UI/logs. NIP-11 reports are hints about limits, not proof that the relay will accept or permanently store an event.

Local outbox states: draft intent → awaiting key → signed+durable → sending → accepted(partial/all) or retryable/terminal failure; cancelled stops unsent work. Store per-relay status and last attempt; no failure reopens the editor or overwrites a later draft. User-visible retry is idempotent. Network status is advisory, not a substitute for attempting/reconciling delivery.

## Long form and short form

Kind30023 content is exact source Markdown. Required d is a cryptographically random128-bit stable lowercase hex identifier assigned once per local article+author; it is not recomputed from title or content. Title is explicit nonempty metadata; optional summary/topics/HTTPS image URL and published_at are stored with the publication revision. published_at is the first *intended* initial publication timestamp and then remains stable; UI distinguishes pending from first relay acceptance. created_at is max(current Unix seconds,last locally published address timestamp+1); do not schedule more than300s into the future—wait/review clock skew rather than forge an implausible time.

Subsequent publication preserves d and published_at and creates a new signed event. naddr addresses the editable article; nevent/exact id identifies the immutable version used in a proof association. Inbound replaceable/addressable resolution uses highest created_at then lowest lexical id for equal times, after signature validation. Client conflicts between unacknowledged local edits and newer remote content require explicit Keep Both; relay ordering is not permission to overwrite the human's draft.

Quick Post uses kind1 with an independent persistent draft; Cmd-Return clears/hides only after enqueue is durably committed. Selection-to-post is explicit copy/import, not a global Accessibility text scrape. Convert Quick Post to Document preserves origin as imported and retains text; it does not replay fabricated keystrokes. No social feed or image upload service is required.

## Encrypted relay-backed drafts

NIP-37 wrapper: kind31234; stable d; required k tag string of target kind (`30023` or `1`); recommended expiration now+90days; content is JSON-stringified **unsigned target event** encrypted by NIP-44 to the same identity's public key. The unsigned event has pubkey, created_at, kind, tags and exact content, no id/sig. Local source and publish metadata are the payload; never include HWP observations, salts, private lineage, keys, absolute paths or other document history.

Use kind10013 for the private relay list: **empty public tags** and self-encrypted JSON private tags `[ ["relay","wss://…"], … ]`. Publish10013 only to the identity's NIP-65 write relays (kind10002 `r` tags with no marker or `write`). On setup, verified remote lists are proposals shown to the user before use. Never silently send draft content to all public posting relays. Private relays should support NIP-42; encryption is still required. The app cannot verify a server's confidentiality/access-control promise.

Local save precedes remote save. Debounce draft sync2s after change, minimum30s between routine versions per draft; explicit Save Draft/close/publish flushes a latest immutable candidate subject to connection/key availability. Persist the encrypted signed wrapper before send. Coalesce unsent older draft versions only after the newest is durable; never discard the only retained local snapshot. Reconnect queries current31234 versions using author and d; verify before decrypt, ignore expired records, resolve ordering, and preserve local conflicts. A recovered draft is external input, not an HWP history. Full histories are not reconstructed from checkpoints. Do not emit optional kind1234 checkpoint history in the MVP; latest draft wraps satisfy relay-backed draft recovery without silently retaining deleted versions.

Deletion uses a newer31234 with blank content for the same d/k; the empty content is a tombstone and must not be decrypted. Send NIP-09 deletion requests for known prior IDs where appropriate, explain best effort and retain no false promise of erasure. Publication does not automatically destroy the private draft; user chooses Keep draft or Remove remote draft. Deleting/rotating a key warns that self-encrypted past drafts may become inaccessible and compromised keys can expose old ciphertext.

## NIP-44 implementation constraints

Use v2 exactly: valid secp256k1 ECDH raw shared-x (not a library's hashed shared-secret default); HKDF extract salt `nip44-v2`; random32-byte nonce; HKDF expand76bytes; IETF ChaCha20 counter0; HMAC-SHA256 over nonce||ciphertext; version byte2 and padded base64. Verify outer Nostr signature before decryption; constant-time MAC before decrypt; strict version/base64/length/point/padding checks. CryptoKit ChaChaPoly is not this construction. Reuse the MIT Swift reference only for protocol composition and adapt its dependency/length assumptions; audit claims from TS/Go/Rust do not automatically cover Swift. [N03,N04]

Current NIP-44 uses a two-byte length for 1..65535 and zero-u16 plus big-endian-u32 for≥65536, theoretical2^32−1. The app cap is1MiB **unsigned draft JSON plaintext**, not body character count. Padding arithmetic is UInt64/checked; extended prefix is never emitted for a shorter message. Accept the official65535/65536/65537 boundary vectors; enforce outer2MiB cap before base64 allocation. A smaller relay can reject even valid ciphertext: retain local source and explain the exact byte limit. Do not fall back to plaintext, deprecated NIP-04 or a proprietary multipart split. Remote NIP-37 interoperable clients may lack current extended support; show this compatibility warning for large drafts, not a universal sync promise.

Recovery arithmetic check against the pinned NIP-44 specification: 65,537 plaintext bytes pad to 81,920 bytes. With the 6-byte extended prefix and 65-byte envelope, the raw payload is 81,991 bytes and padded Base64 is 109,324 characters. This is framing arithmetic, not encryption interoperability evidence.

## Proof association and privacy

Nostr identity keys and HWP Ed25519 roles are distinct. Optional identity binding occurs prospectively as HWP requires. A Nostr signature never creates evaluator/capture approval. When a qualifying matching source.hwp exists, export it and bind its digest to the exact article event in local publication metadata. Optional public discovery via existing NIP-94/ordinary association is enabled only when the user supplies an actual hosted HTTPS proof file and its bytes/digest match. No phantom URL, automatic backend or requirement to publish private history. One-click text publication works without proof hosting.

Encryption does not hide author, event time, network address or all size information and lacks forward secrecy. Remote drafts are opt-in. Never put telemetry or private keys into crash diagnostics, relay URLs, tags or analytics. Relay consent persists separately for public/private use. Nostr failure never prevents local writing, export, or offline proof verification.
