# Focus sessions and offline sound

> Recovered historical preparation; read the [current recovery notice](RECOVERY-NOTES.md) before relying on source availability or test claims.

## Two strengths, no false security claim

Normal Focus is presentation only: hide sidebars/toolbars as selected, optional sentence/paragraph focus, typewriter scroll and sound. Exit immediately. Locked Session is voluntary commitment friction on the selected document: time or net-added-word goal, optional clipboard restrictions, prevention of routine in-app escape, and best-effort system presentation restrictions. It is **not** a system security boundary, cannot defeat an administrator/force quit/reboot/another device, and supplies no independent evidence of human composition.

Use native NSApplication presentation options with valid documented combinations: autoHideDock + autoHideMenuBar + disableProcessSwitching + disableHideApplication where supported and successfully tested. Do not set disableForceQuit or disableSessionTermination; retain system lock, emergency/assistive paths and recovery. Do not rely on beta-only disableScreenCornerInteractions. Save/restore the prior complete options value on every exit/interruption and do not overwrite options changed by unrelated system ownership. Invalid masks can raise exceptions; validate combinations before setting. [A06]

For other attached displays, show neutral app-owned shielding windows without becoming a screen-recording or Accessibility client. Never impersonate system lock/auth prompts. Handle display connection/disconnection, Space changes, Mission Control, Stage Manager and another fullscreen app as tested interruptions; do not promise uncircumventable coverage. If focus protection cannot be maintained, pause the session/progress, release unsafe shields, and explain “Focus protection was interrupted.” Do not start a fight-to-front loop or prevent the user regaining control.

## Goal and clock rules

Exactly one goal per session: time1–240minutes (default25) or net-added words50–20000 (default500). Time counts monotonic active foreground awake time, including thinking pauses, not keystroke duration or wall clock. Sleep, screen lock, app deactivation and protected-environment interruption pause time. Reboot/crash marks the session interrupted; never automatically re-lock on launch. Manual clock changes cannot complete a timer. Runtime after an already reached goal cannot relock the user.

Word goal uses the UI's documented NLTokenizer word count and a fixed start baseline. Progress is min(max(0,currentCount−baseline), eligibleNewWordCount), where an eligible current word has all its non-whitespace/non-punctuation wording roots created by direct entry during this active focus session. Restoring old text, duplicating a word, or undoing an old deletion creates no new eligible roots; delete/undo cannot count the same surviving word twice. This descriptive application lineage is a motivation measure, not HWP. Word-goal Locked sessions automatically disallow external insertion/replace-all/dictation/completion and cross-document import so paste cannot satisfy the displayed target. Direct typing may still be transcription or automation; do not claim otherwise. Deletion can reduce progress below an earlier maximum until completion has already occurred. Native IME text entry remains available; committed words count, marked interim text does not. Include CJK/RTL tests; do not assume whitespace-separated English words.

Timer sessions can choose clipboard restriction Off, Block external insertion, or Block Copy/Cut/Paste. Block external insertion covers paste/plain paste/drag/drop/Services/file-drop/QuickPost-prefill/automatic replacement/menu equivalents in the active editor; it does not require spying on the global clipboard. Internal native undo and navigation remain usable. Full clipboard blocking also disables copy/cut/export-sharing while active; Save and Emergency Exit remain available. No global clipboard clearing. Blocked commands produce one subtle status explanation, not a modal alert per keystroke.

## State machine and safety

States idle → preparing → active → paused/interrupted → active or completed/ended. Preflight identifies DocumentID, goal, baseline, current recording state, restrictions and the emergency exit. Do not start while a file conflict or unsaved-disk failure is unresolved. Persist a lightweight session intent before applying presentation options. Starting a second session or changing the document/goal in place is rejected; end first.

While Locked: disable routine Close/New/Open/Publish/QuickPost/settings changes that escape the chosen task; allow typing, undo, local Save, scrolling, find-only, text accessibility and an always discoverable Emergency Exit. Default exit is keyboard-accessible “End session early…” followed by a10-second countdown with Cancel, not a secret chord or pointer-only hold. All countdown controls work through VoiceOver and keyboard. A crash, system force quit or external terminate remains possible and is not punished. On emergency completion restore options, stop/fade sounds, save/recover text and mark endedEarly. Never delete writing, shame the user or extend the goal as punishment.

A lightweight watchdog checks controller/presentation coherence and outstanding window ownership on app lifecycle notifications; no daemon, kernel process or privileged helper. Loss of ownership restores what the app owns and stops claiming protection. `defer`/termination/resign/error paths restore shields/options; explicit reset on next launch cleans only app-owned session remnants and opens the recovered document normally.

Completion offers Continue Writing, End Session and (timer only) Add10Minutes as a fresh explicit goal. No auto-extension. Sounds fade but writing focus stays stable. Timer/word state is independent from HWP recording boundaries; a completed session never promotes NOT PROVABLE.

## Sounds

All sounds are offline, optional and initially off. Four named options: Tick, Rain, Café and Brown Noise, plus volume0–100% constrained to safe digital headroom and a mute shortcut/menu item. Use AVAudioEngine/AVAudioPlayer with click-free loops,250ms fade-in/out and no startup sound. Tick and brown noise can be synthesized; rain may use a generated naturalistic noise layer. Café requires a properly licensed non-identifying ambient recording with no intelligible identifiable conversations; use a bundled CC0/public-domain/owned asset with provenance and licence stored in `assets/SOUND-SOURCES.md`, or record a synthetic nonverbal café ambience from owned foley. Do not download an unlicensed commercial ambience or ship a placeholder while claiming the required sound complete.

Rendering assets during implementation is allowed; runtime never fetches a soundtrack or requests the microphone to play sounds. Output follows the system audio device; headphone removal, device change, sleep, app quit and session interruption fade/stop safely. Sounds never start because the user merely opens the preferences pane. Every item is auditionable outside a Locked session and respects the persistent chosen volume. Long-run tests watch CPU, memory, clicks and leaked audio engines; no blanket requirement for exclusive audio focus.
